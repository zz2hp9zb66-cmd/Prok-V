# Collage B-Roll: технический анализ, архитектура и план MVP

Этап 1 — только проектирование. Код не пишется, зависимости не устанавливаются.

---

## 1. Можно ли это сделать

**Да, цепочку целиком можно собрать на бесплатных инструментах и запускать на macOS.** Но этапы автоматизируются в разной мере:

| Этап | Автоматизация | Комментарий |
|---|---|---|
| Разбор сценария на сцены, список нужных визуалов | Высокая | Делает сам Claude Code (LLM внутри сессии), отдельный API не нужен |
| Поиск изображений | Средняя | Хорошо работает для архивов и свободных банков. Для коммерческих/редких фото (конкретные обложки, сессии в студии) результат часто неполный |
| Проверка лицензий | Низкая/средняя | Метаданные открытых архивов можно прочитать. Юридически надёжного автоматического вывода нет — только пометки «разрешено / проверить / запрещено» |
| Удаление фона | Высокая | Хорошо для портретов и отдельных предметов. Плохо на групповых фото, волосах на шумном фоне, тонких деталях |
| Вырезание конкретного объекта по описанию («труба», «саксофонист слева») | Средняя | Цепочка «детектор по тексту → SAM 2». Нужно утверждение человеком |
| Композиция коллажа | Средняя/высокая | Шаблоны + правила + случайность с фиксированным seed. «Вкус» дорабатывается при утверждении |
| Анимация, переходы, камера | Высокая | Библиотека пресетов, детерминированная сборка |
| Рендер MP4 1080×1920/30fps | Высокая | Remotion + FFmpeg |
| Редактируемый проект для DaVinci Resolve | Средняя/высокая | Слои с альфой + таймлайн FCPXML/OTIO |
| Редактируемый проект для CapCut | **Низкая** | Открытого формата проекта нет — см. §6 |

Главные ограничения — **права на изображения** и **качество найденных исходников**. Код здесь не поможет, поэтому обязательные ручные этапы утверждения — часть архитектуры, а не временная мера.

## 2. Архитектура

### 2.1 Принципы

1. **Папка проекта — единственный источник истины.** Всё состояние хранится в JSON-файлах на диске. Любой этап можно перезапустить, Claude Code может читать и править любой файл.
2. **Конвейер из независимых этапов.** У каждого этапа есть вход и выход в виде файлов. Этап можно запустить для всего проекта или для одной сцены (`--scene 03`).
3. **Идемпотентность и кэш.** Результат этапа помечается хэшем входных данных: если сцена не менялась, её не пересчитывают.
4. **Оригиналы неизменны.** Скачанные файлы только читаются, все производные лежат отдельно.
5. **Один рендерер для превью и финала.** Превью коллажа — это кадр того же рендера Remotion, что и финальное видео. Поэтому утверждённое совпадёт с тем, что выйдет в видео.
6. **Описание сцены отделено от времени.** Композиция (`scene.json`) и длительность (`timeline.json`) хранятся в разных файлах. Если поменять длительность, композицию собирать заново не нужно.

### 2.2 Схема конвейера

```
script.md
   │
   ▼
[1 analyze] ──► scenes/*/scene.json (текст, смысл, список визуальных «запросов»)
   │                 timeline.json (длительности по темпу)
   ▼
[2 search] ───► assets/originals/<id>.<ext> + assets/meta/<id>.json (URL, автор, лицензия)
   │                 scenes/*/candidates.json (ранжированные кандидаты)
   ▼
[3 review-images] ◄── ПОЛЬЗОВАТЕЛЬ: утверждает/заменяет фото (contact sheet)
   ▼
[4 cutout] ───► assets/cutouts/<id>.png (RGBA), masks/<id>.png, стилизованные варианты
   ▼
[5 compose] ──► scenes/*/scene.json: слои, позиции, масштаб, поворот, z, глубина
   │                 previews/scene_03.png
   ▼
[6 review-storyboard] ◄── ПОЛЬЗОВАТЕЛЬ: утверждает / просит переставить / пересобрать
   ▼
[7 animate] ──► scenes/*/scene.json: блок animation (пресеты, seed, тайминги)
   ▼
[8 render] ───► renders/scenes/scene_03.mp4 (+ слои с альфой)
   ▼
[9 assemble] ─► output/final.mp4 (H.264, 1080×1920, 30fps, без звука)
   ▼
[10 export] ──► export/resolve/*.fcpxml, *.otio, layers/, credits.md, capcut/
```

### 2.3 Структура проекта на диске

```
projects/blue-note-001/
  project.json            # настройки: темп, fps, разрешение, стиль, seed
  script.md               # исходный сценарий
  timeline.json           # длительности сцен, переходы, отступы для переходов
  credits.md              # автогенерация: источники и лицензии
  scenes/
    01/
      scene.json          # смысл, слои, композиция, анимация, статус утверждения
      candidates.json
      notes.md            # правки пользователя в свободной форме
  assets/
    originals/            # скачанные файлы — не изменяются
    meta/                 # JSON на каждый файл: url, автор, лицензия, статус проверки
    cutouts/              # PNG с прозрачностью
    masks/
    styled/               # обводка, тени, рваный край, дуотон
    backgrounds/
    textures/             # бумага, зерно, скотч (CC0)
    text/                 # отрендеренные текстовые элементы (PNG) + исходные параметры
  previews/               # кадры раскадровки, contact sheets, storyboard.html
  renders/
    scenes/               # MP4 по сценам
    layers/               # ProRes 4444 / PNG-последовательности по слоям
  output/final.mp4
  export/
    resolve/              # FCPXML + OTIO + ссылки на медиа
    capcut/               # медиа-пакет + инструкция
  logs/
```

### 2.4 Модули кода (будущие)

- **`core`** (Python) — модели данных (Pydantic-схемы `Project`, `Scene`, `Layer`, `Asset`, `Timeline`), чтение/запись JSON, хэши, кэш.
- **`search`** (Python) — адаптеры источников с общим интерфейсом `search(query) -> [Candidate]`, загрузчик, нормализатор лицензий.
- **`rank`** (Python) — фильтры качества, дедупликация, релевантность через CLIP.
- **`cutout`** (Python) — удаление фона, сегментация по тексту, постобработка маски, стилизация.
- **`compose`** (Python) — движок раскладки: шаблоны + ограничения → координаты слоёв.
- **`renderer`** (TypeScript, Remotion) — React-компоненты `Collage`, `Layer`, `PaperText`, `CameraRig`, библиотека пресетов анимации и переходов. На входе — только JSON.
- **`export`** (Python) — FFmpeg-обёртки, генерация FCPXML/OTIO, credits.
- **`cli`** — единая команда (например, `cbroll analyze|search|cutout|compose|preview|animate|render|export [--scene N]`).
- **`.claude/commands/`** — slash-команды Claude Code, оборачивающие этапы: `/cb-new`, `/cb-review`, `/cb-fix-scene 3 "замени фото на более раннее"`.

Python и Node связаны только через файлы: Python пишет JSON, Remotion его читает. Им не нужно вызывать друг друга.

## 3. Инструменты по этапам

### 3.1 Разбор сценария
- **Claude Code** (в сессии): разбивает текст на смысловые сцены и для каждой выдаёт `visual_queries` — персоны, предметы, места, эпоха, настроение, ключевая фраза для типографики — плюс поисковые запросы на нескольких языках (англоязычные архивы дают в разы больше результатов).
- Результат проверяется по Pydantic-схеме, при ошибке Claude Code исправляет JSON сам.
- Без интернета это работает, только если LLM запущена локально (Ollama и т. п.) — качество будет заметно хуже. Для этой задачи рекомендую Claude Code.

### 3.2 Поиск изображений (нужен интернет)

| Источник | Что там есть | Доступ | Лицензия в метаданных |
|---|---|---|---|
| **Wikimedia Commons** (MediaWiki API) | Портреты музыкантов, города, инструменты, часть архивных фото | Бесплатно, без ключа (нужен User-Agent) | Да, машиночитаемо (`extmetadata`) |
| **Openverse** (API) | Агрегатор CC-изображений (Flickr, музеи) | Бесплатно, ключ по желанию | Да |
| **Library of Congress** (loc.gov JSON API) | Американская история, в т.ч. джазовые фото William P. Gottlieb (public domain) — идеально для темы Blue Note | Бесплатно | Частично, есть поле rights |
| **Smithsonian Open Access** | Музейные предметы, инструменты | Бесплатный ключ api.data.gov | CC0 |
| **The Met / Rijksmuseum / Art Institute of Chicago** | Предметы, гравюры, типографика | Бесплатно (у Rijksmuseum ключ) | В основном CC0/PD |
| **Europeana** | Европейские архивы | Бесплатный ключ | Да (rights statements) |
| **Internet Archive** | Сканы журналов, афиш | Бесплатно | Часто неизвестна → ручная проверка |
| **Flickr** (вкл. Flickr Commons) | Архивы организаций | Бесплатный ключ | Да |
| **Pexels / Unsplash / Pixabay** | Современный сток: фактуры, инструменты, города | Бесплатные ключи, есть лимиты | Собственные лицензии сайтов (не CC) |
| **MusicBrainz + Cover Art Archive** | Обложки альбомов | Бесплатно | **Обложки защищены авторским правом** → всегда «ручная проверка» |
| Discogs API | Обложки, фото артистов | Бесплатный токен | Права не указаны → ручная проверка |

**Общий поиск по интернету (Google/Bing).** Бесплатного и стабильного официального API для поиска картинок нет. Google Custom Search JSON API закрыт для новых клиентов, и о его отключении уже объявлено. Платные API (Bing/Brave/SerpAPI) можно подключить позже как отдельный модуль, но в MVP **не закладываю**: они почти всегда возвращают изображения с неизвестными правами.

**Ранжирование кандидатов — локально:**
- фильтр по разрешению (например, не меньше 1000 px по длинной стороне для главного объекта);
- дедупликация по perceptual hash (`imagehash`);
- релевантность «текст ↔ картинка» через **OpenCLIP / SigLIP** (бесплатно, работает на Apple Silicon через PyTorch MPS);
- приоритет лицензии: PD/CC0 > CC BY > CC BY-SA > прочие > неизвестно;
- Claude Code может сам просмотреть contact sheet (он видит изображения) и отсеять явно неподходящие варианты до показа пользователю.

### 3.3 Подготовка изображений (всё локально, бесплатно)

| Задача | Инструмент | Примечание |
|---|---|---|
| Удаление фона, общий случай | **rembg** с моделями **BiRefNet** / ISNet | MIT/Apache, хорошее качество, оффлайн после загрузки весов |
| Удаление фона средствами macOS | **Apple Vision** (`VNGenerateForegroundInstanceMaskRequest`, macOS 14+) через небольшой Swift CLI или pyobjc | Бесплатно, быстро, очень хорошо на людях. Отдельная маска для каждого объекта |
| Выделение конкретного объекта по тексту | **Florence-2** или **OWLv2 / Grounding DINO** (текст → рамка) + **SAM 2** (рамка → маска) | Всё локально. Вес моделей — сотни МБ … пара ГБ |
| Доводка краёв | `pymatting` (alpha matting), морфология OpenCV | Нужна для волос и мягких краёв |
| Стиль «бумажная вырезка» | Pillow + OpenCV + numpy | Белая обводка (расширение маски), тень, рваный край (маска со смещением по шуму), полутон, дуотон, зерно, лёгкая перспектива |
| Тексты и типографика | Шрифты Google Fonts (лицензия OFL), рендер в Remotion; при необходимости дублирование в PNG | Например: Bebas Neue, Oswald, Playfair Display, Space Grotesk, кириллические гарнитуры |
| Бумажные текстуры | Процедурная генерация + CC0-библиотеки (ambientCG, Poly Haven) | Скотч, сгибы, крафт, газетная бумага |
| Апскейл слабых архивных фото (опционально) | Real-ESRGAN (локально) | Может «додумать» детали → только по явному запросу |

⚠️ **BRIA RMBG** не подходит: качество хорошее, но лицензия запрещает коммерческое использование без договора.

### 3.4 Композиция
- **Шаблоны раскладки** (8–12 штук на старте): «герой + архивный фон + 2 предмета + заголовок», «сетка из обложек», «газетная полоса», «диагональный каскад», «рамка-поляроид», «крупный план + цитата» и т. д.
- Движок раскладки на Python: зоны безопасности для 9:16 (верх и низ под интерфейс соцсетей), минимальный размер лица, допустимое перекрытие, баланс по весу, 3–5 слоёв глубины (background / mid / foreground / text / overlay).
- Случайность (небольшие повороты ±2–8°, сдвиги, выбор текстуры) с **seed для каждой сцены** — пересборка воспроизводима, а «перебросить кости» значит сменить seed.

### 3.5 Анимация и рендер
**Рекомендуемый движок — Remotion** (React + TypeScript, рендер через Chromium + FFmpeg).

Почему он:
- описание сцены в JSON напрямую превращается в props компонента — идеально для автоматизации через Claude Code;
- `interpolate`, `spring`, `@remotion/transitions` (slide, wipe, fade и др.) и собственные переходы (рваная бумага, скотч);
- **Remotion Studio** — локальный интерактивный просмотр с таймлайном, а при описании props через Zod — визуальный редактор параметров;
- `renderStill` — для кадров раскадровки, `renderMedia` — для MP4 и ProRes 4444 с альфой.

**Лицензия Remotion:** бесплатно для частных лиц и компаний до 3 сотрудников, крупнее — платная company license. Это нужно учесть сразу.

Альтернативы и почему не они:
- **MoviePy / чистый FFmpeg** — бесплатно и просто, но сложную многослойную анимацию с easing, параллаксом и переходами писать и поддерживать сильно тяжелее.
- **Blender** (бесплатный, настоящий 2.5D, камера, свет) — мощно, но рендер медленнее, управление из Python заметно сложнее. Хороший кандидат на «режим 2» в будущем.
- **After Effects / Motion** — платные, не подходят под приоритеты.

**Библиотека пресетов («глаголов» движения):** появление (fade+scale, drop с отскоком, slide-in, «наклейка» — pop с поворотом, маска-раскрытие, «stop-motion» с джиттером 12 fps на двойках), удержание (дрейф, лёгкое покачивание, «дыхание» масштаба), камера (Ken Burns, параллакс по глубине, наклон, push-in, whip-pan), текст (печатная машинка, по словам, «вырезанные буквы»), переходы (рваная бумага, slide со скотчем, flash-cut, zoom-through).

**Против однотипности:** правило в генераторе — соседние сцены не должны повторять пресет камеры и тип перехода; у каждого слоя смещение старта по глубине (stagger); веса пресетов зависят от темпа.

### 3.6 Сборка и экспорт — FFmpeg
- Финальный файл: H.264 High, `yuv420p`, 1080×1920, 30 fps CFR, `-an` (без звука), `+faststart`.
- Слои: ProRes 4444 с альфой (`.mov`) или PNG-последовательности.
- Склейка сцен — см. §7.

| Поиск изображений | — | **Обязательно** (бесплатные API архивов) |
| Скачивание, метаданные лицензий | — | Обязательно |

| Шрифты | ✅ | Загрузка один раз |
| Композиция, превью, анимация | ✅ | — |

| Правки «замени фото на более раннее» | Логика локально | Новый поиск — через интернет; рассуждение — Claude Code |

Платные API для MVP **не нужны**. Опционально в будущем: платный поиск картинок и генерация недостающих элементов ИИ (с пометкой «сгенерировано»).

## 5. Ограничения автоматического поиска и обработки — честно

1. **Авторское право.** Большинство самых узнаваемых изображений по теме не являются свободными. Для Blue Note это обложки (дизайн Рида Майлза) и фотографии Фрэнсиса Вольфа: права на них принадлежат владельцам каталога и архивам. Система будет их находить и **помечать `manual_review`**, но не будет утверждать, что их можно использовать. Решение о fair use / лицензировании принимает пользователь.
2. **Метаданные о лицензиях неполные или ошибочные.** Даже на Wikimedia встречаются неверно загруженные файлы. Статус «разрешено» означает «источник заявляет разрешённую лицензию», а не юридическую гарантию.
3. **Опознать человека автоматически нельзя.** Я не закладываю распознавание лиц знаменитостей: это ненадёжно и спорно этически. Система опирается на подписи и метаданные архива («Art Blakey, 1955»), а на этапе утверждения пользователь подтверждает, что на фото нужный человек. Ошибки подписей в архивах встречаются.
4. **Архивное качество.** Низкое разрешение, зерно, царапины, ч/б. Для стиля коллажа это часто плюс, но крупный план в 1080×1920 из файла 600 px будет мыльным → правило минимального размера для каждой роли слоя.
5. **Сегментация ошибается** на групповых фото (люди перекрываются), волосах на пёстром фоне, тонких деталях (клапаны трубы, стойки тарелок, грифы), прозрачных/блестящих предметах, при низком контрасте ч/б фото. В эстетике paper cutout это частично маскируется толстой белой обводкой и намеренно «грубой» вырезкой — используем это как стилистическое решение.
6. **Водяные знаки и мусор.** Превью со стоков и сайтов могут содержать водяные знаки. Удалять их система не будет: это нарушение. Такие изображения отбрасываются.
7. **Узкие темы находятся плохо.** Чем уже факт («студия Руди Ван Гелдера в Хакенсаке, 1952»), тем меньше свободных изображений. Нужны запасные стратегии: фото эпохи/места вообще, предмет-символ, типографика вместо фото.
8. **Лимиты API** и требования к User-Agent: нужны кэш запросов, паузы, повторные попытки.
9. **Credits обязательны.** Для CC BY / BY-SA система автоматически собирает `credits.md` (автор, название, ссылка, лицензия). Указывать атрибуцию в публикации — ответственность пользователя.

## 6. Предварительный просмотр и утверждение

Два уровня, оба локальные:

**A. Статическая раскадровка (основной путь, MVP)**
- `previews/storyboard.html` — локальная страница: для каждой сцены текст фрагмента, кадр коллажа (рендер Remotion `renderStill`, ключевой кадр «всё на месте»), длительность, список слоёв с источником и статусом лицензии, кнопки-подсказки с готовыми командами.
- `previews/scene_03_candidates.jpg` — contact sheet с пронумерованными кандидатами для каждого слота.
- Утверждение и правки — **в чате Claude Code** естественным языком или короткими командами:
  - «Сцена 2 ок» → `status: approved`;
  - «Сцена 3: портрет замени на кандидата #5» → меняется `asset_id` слоя, пересобирается только сцена 3;
  - «Сцена 3: портрет левее и крупнее, заголовок вниз» → Claude Code правит `transform` в `scene.json` → новый кадр;
  - «Сцена 4: пересобери с другим шаблоном / другим seed».
- Анимация (этап 7) запускается **только** если у всех сцен `status: approved`. Это проверяется в коде, а не держится на договорённости.

**B. Интерактивный просмотр (этап 2 развития)**
- Remotion Studio (`localhost`) — проигрывание сцены, прокрутка, правка props через схему Zod.
- Позже — небольшой локальный редактор (drag-and-drop слоёв поверх превью), который записывает координаты прямо в `scene.json`. Он не нужен для MVP, но архитектура это позволяет, потому что всё состояние хранится в JSON.

## 7. Время и темп

- Длительность сцены = `max(min_dur, слова / WPM × 60) + запас на появление и уход`, где WPM зависит от темпа и языка:
  - медленный — ~110 слов/мин (рус.) / ~130 (англ.), минимум 4 с;
  - средний — ~130 / ~150, минимум 3 с;
  - динамичный — ~150 / ~175, минимум 2 с, больше коротких сцен и резкие переходы.
- `timeline.json` хранит `duration_frames` каждой сцены, тип и длину перехода, а также флаг `locked`, если длительность задана вручную (например, позже под озвучку).
- **Анимация задаётся относительно длительности сцены:** тайминги пресетов — в долях и с ограничениями («появление 12–20 кадров, остальное — удержание и дрейф»). Изменение длительности → перерендер только этой сцены, композиция не трогается.
- **Переходы и перерендер одной сцены.** Переход занимает кадры двух соседних сцен. Решение: каждая сцена рендерится с запасом кадров (handles, например 15 кадров с каждой стороны), а переходы собираются на этапе `assemble` отдельными короткими клипами. Тогда перерендер сцены 3 затрагивает только сцену 3 и два перехода рядом с ней.
- **Под будущую озвучку:** можно задать длительности вручную или (позже) автоматически по тайм-кодам — Whisper локально даёт пословную разметку. Тогда сцены выравниваются по речи без пересборки композиций.

## 8. Редактируемый экспорт

### 8.1 DaVinci Resolve — рекомендуемая схема

Рекомендую **комбинированный пакет**, а не один формат:

1. **Слои с альфой, уже анимированные** — для каждого слоя сцены отдельный клип ProRes 4444 `.mov` 1080×1920 с прозрачностью (на диске тяжело, но это самый надёжный вариант).
2. **Таймлайн FCPXML (1.9/1.10)** — Resolve импортирует его штатно (File → Import → Timeline). Каждая сцена — набор дорожек V1…Vn в порядке глубины, клипы на своих местах по времени. Пользователь может двигать клипы, менять время появления, длительность, масштаб и позицию через Inspector.
3. **OpenTimelineIO (`.otio`)** — дубль таймлайна в открытом формате; новые версии Resolve импортируют его напрямую. Он же служит основой для будущих экспортов в другие программы.
4. **Статические исходники** — PNG вырезок, фоны, текст (PNG + параметры шрифта в JSON), чтобы элемент можно было анимировать в Resolve заново.
5. **Финальный MP4 и MP4 по сценам** — для быстрого монтажа «целыми блоками».

Чего **не обещаю** в MVP:
- переноса ключевых кадров анимации Remotion в нативные keyframes Resolve. FCPXML умеет параметры трансформации, но импорт анимированных keyframes в Resolve ненадёжен. Для «живых» правок движения — путь 1 (переставить или заменить анимированный слой) или путь 4 (заново анимировать статичный PNG);
- генерации Fusion-композиций (текстовый формат `.setting`/`.comp` с нодами и keyframes) — технически возможно, но это отдельная сложная задача, кандидат на этап 3;
- управления Resolve через Python API: внешний scripting в бесплатной версии ограничен, это нужно проверить на конкретной версии.

Если слоёв много, их число на сцену стоит ограничить (например, 4–7, мелкие декоративные элементы объединять в один слой «overlay»).

### 8.2 CapCut — что реально возможно

- У CapCut **нет открытого и документированного формата проекта**. Внутренний `draft_content.json` недокументирован, меняется от версии к версии, а в новых версиях проекты шифруются. Сторонние генераторы черновиков (для JianYing/CapCut) существуют, но ломаются при обновлениях — **закладывать их в основной путь нельзя**.
- Реалистичный вариант: папка `export/capcut/` с
  - MP4 по каждой сцене (сразу в монтаж);
  - PNG-вырезками и фонами (в CapCut их можно положить как overlay и анимировать keyframes);
  - анимированными слоями: поддержка импорта видео с альфой в CapCut зависит от версии и платформы, это нужно проверить. Запасной вариант — слой на хромакее для встроенного Chroma Key;
  - `timeline.csv` / `timeline.pdf` — шпаргалкой «какой слой, с какой секунды, сколько длится».
- Итог: в CapCut — **ручная сборка из готовых элементов** с удобной шпаргалкой, а не открытие проекта «как есть».

## 9. Пошаговый план MVP

Каждый шаг заканчивается проверяемым результатом.

**Шаг 0 — Окружение (macOS, Apple Silicon рекомендуется, ≥16 ГБ RAM).** Homebrew, Python 3.11+ (uv), Node 20+, FFmpeg. Скелет репозитория, схемы данных, CLI-заглушки. *Результат:* `cbroll new` создаёт папку проекта.

**Шаг 1 — Модели данных и разбор сценария.** Pydantic-схемы, slash-команда `/cb-new`, через которую Claude Code пишет `scene.json` для каждой сцены и `timeline.json` по темпу. *Результат:* сценарий из 4 абзацев → 4 сцены с запросами и длительностями.

**Шаг 2 — Поиск: Wikimedia Commons + Openverse + Library of Congress.** Адаптеры, загрузка, `meta/*.json`, нормализация лицензий, кэш. *Результат:* для каждого визуального запроса — 5–15 кандидатов с лицензиями.

**Шаг 3 — Ранжирование и contact sheets.** Фильтры, phash, CLIP-скоринг, генерация `scene_XX_candidates.jpg`. **Точка утверждения №1** (выбор фото). *Результат:* утверждённые `asset_id` в каждой сцене.

**Шаг 4 — Вырезка.** rembg/BiRefNet + Apple Vision как альтернатива, SAM 2 по рамке, стилизация (обводка, тень, рваный край, зерно). *Результат:* RGBA PNG + маски, contact sheet вырезок для проверки.

**Шаг 5 — Remotion-рендерер статики.** Компоненты слоёв, бумага, текст, 3–4 шаблона раскладки, `renderStill`. *Результат:* `previews/scene_XX.png` + `storyboard.html`.

**Шаг 6 — Цикл правок.** Команды замены фото, сдвига и масштаба слоя, смены шаблона и seed; пересборка одной сцены. **Точка утверждения №2** (раскадровка). *Результат:* все сцены `approved`.

**Шаг 7 — Анимация.** 8–10 пресетов появления, 3–4 камеры, 3 перехода, правило «без повторов подряд», запуск только после утверждения. *Результат:* MP4 каждой сцены с запасом кадров.

**Шаг 8 — Сборка.** Переходы, склейка, финальный MP4 по спецификации и проверка через `ffprobe` (1080×1920, 30 fps, нет аудиопотока). *Результат:* `output/final.mp4`.

**Шаг 9 — Экспорт.** Слои ProRes 4444, FCPXML + OTIO, `credits.md`, пакет для CapCut. *Результат:* таймлайн открывается в DaVinci Resolve, слои на своих местах.

**Шаг 10 — Изменение длительности без пересборки.** `cbroll retime --scene 2 --seconds 6.5` → перерендер сцены 2 и соседних переходов, обновление FCPXML. *Результат:* проверка, что остальные сцены не перерендерились (по кэшу).

Позже: Europeana/Smithsonian/Met, Blender-режим, локальный drag-and-drop редактор, выравнивание по озвучке через Whisper, Fusion-экспорт.

## 10. Минимальный тест

**Сценарий (≈25 секунд, средний темп, 4 сцены):**

1. «В 1939 году в Нью-Йорке двое эмигрантов из Берлина, Альфред Лайон и Фрэнсис Вольф, основали маленький джазовый лейбл.»
2. «Они записывали музыкантов ночью, после концертов, и платили им даже за репетиции.»
3. «Звук рождался в гостиной Руди Ван Гелдера, а обложки превращали пластинки в произведения графического дизайна.»
4. «Так Blue Note стал голосом хард-бопа — от Арта Блэйки до Джона Колтрейна.»

**Ожидаемые визуалы и где их искать:**

| Сцена | Слои | Вероятный источник / риск |
|---|---|---|
| 1 | Нью-Йорк конца 1930-х (фон), пароход/эмиграция, заголовок «1939» | LoC, Wikimedia — PD найдётся. Фото самих Лайона и Вольфа, скорее всего, несвободные → `manual_review` или замена на типографику |
| 2 | Музыканты в клубе ночью, микрофон эпохи, часы | Фото Готтлиба (LoC, PD) — хорошая находка |
| 3 | Студийный микрофон, магнитофон, «обложка» | Реальные обложки — `manual_review`. Запасной вариант — стилизованная обложка из типографики и PD-фото |
| 4 | Портреты Блэйки и Колтрейна, барабаны, саксофон, крупный заголовок | Wikimedia/LoC (часть фото есть под свободными лицензиями), инструменты — Smithsonian/Pexels |

**Критерии приёмки:**
- 4 сцены, у каждой ≥3 слоя на ≥3 уровнях глубины, ≥1 вырезка с прозрачностью;
- в каждой сцене разный пресет камеры, ≥2 разных типа переходов;
- `output/final.mp4`: 1080×1920, 30 fps, нет аудио, длительность 20–30 с;
- у каждого изображения есть `meta/*.json` с URL и лицензией, `credits.md` сгенерирован, несвободные помечены;
- пересборка одной сцены не трогает остальные (видно по логам и кэшу);
- изменение длительности сцены 2 даёт новый финал без повторного поиска и вырезки;
- FCPXML открывается в DaVinci Resolve, слои лежат на отдельных дорожках, их можно двигать.

## 11. Технические риски и ограничения

| Риск | Вероятность | Влияние | Как снижаем |
|---|---|---|---|
| Нет свободных фото по узкой теме | Высокая | Высокое | Запасные стратегии (эпоха/символ/типографика), `manual_review`, возможность подложить свои файлы в `assets/inbox/` |
| Неверные или неполные лицензии | Средняя | Высокое (юридическое) | Только статусы, без «гарантий», обязательный credits, ручное утверждение |
| Неверно подписанные архивные фото | Средняя | Среднее | Подтверждение человеком на этапе 1 |
| Плохие маски на сложных фото | Высокая | Среднее | Два движка (BiRefNet / Apple Vision), SAM 2 с рамкой, грубая белая обводка как стиль, ручная замена |
| Однообразные коллажи | Средняя | Среднее | Больше шаблонов, правила разнообразия, seed, правки при утверждении |
| Скорость рендера Remotion на длинных видео | Средняя | Низкое | Посценовый рендер, кэш, параллельность; 30 с видео — минуты, не часы |
| Объём ProRes 4444 | Высокая | Низкое | Ограничить число слоёв, опция PNG-последовательностей, экспорт слоёв по запросу |
| Импорт FCPXML/OTIO в Resolve зависит от версии | Средняя | Среднее | Тест на вашей версии Resolve в шаге 9, оба формата параллельно |
| CapCut: нет открытого формата | Точно | Среднее | Медиа-пакет + шпаргалка; генераторы черновиков — только экспериментально |
| Лицензия Remotion при росте команды | Низкая/средняя | Среднее | Учитывать заранее; рендерер изолирован за JSON-интерфейсом и заменяем (Blender/MoviePy) |
| Веса моделей (несколько ГБ) и память | Средняя | Низкое | Загрузка по требованию, Apple Vision как лёгкий вариант |
| Изменения или лимиты бесплатных API | Средняя | Среднее | Адаптеры с общим интерфейсом, кэш, несколько источников |
| Модели с некоммерческими лицензиями (BRIA RMBG и т. п.) | Средняя | Высокое | Белый список моделей с проверенными лицензиями (MIT/Apache/BSD) |
